Selected work

Three agents. Three levels of autonomy.

Each project applies AI to a different enterprise function: engineering, delivery and commercial. In each one, the autonomy and controls match the risk of the process.

01 · EngineeringAutonomous agent + MCP

Autonomous, change-aware regression testing

An AI Test Automation Agent that understands what is changing, selects the right regression tests, runs them, logs bugs and notifies teams, end to end with no manual steps.

Change→Understand→ Select→Test→ Detect→Act
The challenge

Regression on a legacy tool was hard to manage. Quarterly and ad-hoc cycles needed manual effort from roughly 10–15 service-line teams, slowing major upgrades to production.

The approach
  • Reads PRs, change requests, bugs, features and tech debt in Azure DevOps
  • Selects the relevant regression suite
  • MCP exposes skills to the agent
The outcome
  • Automatic execution and result capture
  • Bugs created automatically
  • Teams notified, zero intervention
Read the architecture

At the center is an AI Test Automation Agent that orchestrates the regression lifecycle. MCP is the capability layer: it exposes skills that let the agent work with engineering systems, the test suite and the enterprise application.

The cycle starts from change intelligence, understanding what is moving toward deployment, and continues through regression selection, autonomous execution, result analysis, defect creation and team notification.

AI shouldn't only give answers. It should understand enterprise context and take part in end-to-end workflows.
02 · DeliveryConversational + human-in-the-loop

AI Delivery Agents for project managers

A Copilot-style agent that lets project managers plan, forecast, staff and manage projects in natural language, and proactively flags projects that are falling behind.

Ask→Interpret→ Propose→Confirm→ Update→Alert
The challenge

Every action was UI-driven and unintuitive. Project data went stale, which led to inaccurate health reporting to leadership, project hygiene issues and incorrect financial reporting.

What it can do
  • Dates, schedules, team and responsibilities
  • Staffing and finding capabilities
  • Project end-date extensions and team-member changes
  • Resource-mix cost changes, forecasts, EAC and ETC
Designed for trust
  • Every data change confirmed by the user
  • Proactive alerts tied to each project's risk register
  • PMs manage projects, not screens
Read the full story

The real problem wasn't missing data. It was a usability problem at the front line that grew into a data quality, governance and financial accuracy problem at the leadership level.

By letting project managers describe what they want instead of navigating screens, the agent goes after the root cause. Updates get easier, so data stays current. Built-in logic linked to each project's risk register lets the agent reach out first when updates are overdue.

The agent proposes and alerts. The human decides.
03 · CommercialConversational + built-in validation

Deal Management Agent

An agent that speeds up the deal lifecycle, covering catalog onboarding, custom offers and amendments, while building governance into the workflow.

Describe→De-duplicate→ Billing→Pricing→ Provisioning→Review
The challenge

Fast-changing business models need flexibility beyond standard offerings. Teams faced slow SKU onboarding, duplicate SKUs, multi-team approvals and, hardest of all, contractual amendments.

Who felt it
  • Sales teams
  • Deal desk
  • Finance
  • Catalog owners
The solution
  • Easy SKU, product and catalog creation with duplication checks
  • Custom offers in natural language
  • Amendments pre-validated before submission
Read the full story

Before, agility and governance pulled against each other: flexibility meant risk, and control meant delay. Every new catalog item now goes through a layered review: a duplication check, then validation against billing, pricing and provisioning, then review by partner teams.

Amendments, the most error-prone step, are validated before they reach backend systems, so problems are caught early, when they cost least to fix.

Make the right thing the easy thing. When validation is automatic, speed and quality stop being trade-offs.

How I think about Enterprise AI

Match autonomy to risk.

Not every workflow should get the same level of AI independence. The design question isn't "can AI do this?" It's "how much should AI decide on its own here?"

Human decides

Delivery Agents

Financial and project data: the agent proposes, and the PM confirms every change.

Validation built in

Deal Management

Commercial changes: automated checks plus review by human owners.

Fully autonomous

Regression Testing

Engineering validation: the agent runs the whole cycle by itself.
